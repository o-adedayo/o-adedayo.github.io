CASE-002 — Shadow Copy Deletion on a Production SQL Server: Deconflicting a Ransomware Precursor (T1490)

1. Executive Summary

Our third-party managed SOC called to escalate a high-severity EDR detection: all volume shadow copies had just been deleted on a client's production SQL server using vssadmin.exe — the single most common command ransomware operators run immediately before encryption. I led triage on the MSP side, assessed the telemetry as consistent with hands-on administrative activity rather than automated malware, and ran a verification-first deconfliction: a direct phone call to the client's IT administrator, backed by written email confirmation. The administrator confirmed he had deleted the shadow copies himself while troubleshooting a failing backup product. The alert was closed as a benign true positive, and a request from the client to "pause protection" during his maintenance was converted into a narrowly scoped, time-boxed alert suppression instead — keeping the server fully protected throughout. No compromise, no impact, and the detection pipeline was validated end to end.

2. Detection

  • A Datto EDR behavioral rule fired on execution of vssadmin.exe delete shadows /all /quiet on a production SQL server, mapped to ATT&CK T1490 (Inhibit System Recovery) at High severity.
  • The signal identified the executing account as a named domain administrator, with a process lineage of explorer.exe → powershell.exe → vssadmin.exe and a plain, unobfuscated command line.
  • The managed SOC escalated by phone rather than ticket — appropriate for this alert class, because in genuine intrusions shadow copy deletion precedes encryption by minutes, and a compromised domain admin on a database server represents maximum blast radius.

Telemetry involved: Datto EDR process telemetry (command line, process lineage, file signature metadata, binary reputation), RocketCyber managed SOC incident record.

3. Triage & Scoping

The core analytical problem: vssadmin.exe is a Microsoft-signed, entirely legitimate administration utility (a LOLBin). The binary's reputation is meaningless — a 0-detection VirusTotal score is expected. Disposition rests entirely on context: who ran it, how, and what surrounded it. Two hypotheses fit the same telemetry: (a) an administrator doing routine VSS maintenance, common on SQL servers where shadow storage grows aggressively, or (b) a hands-on-keyboard intruder operating a stolen admin account in the pre-encryption phase of a ransomware operation — who would type exactly the same command.

Before any contact, I scoped the telemetry to weight the hypotheses:

Working assessment: probable authorized maintenance — but indistinguishable from a compromised-account scenario on telemetry alone. Severity held at SEV-2 and the EDR-recommended containment path (host isolation + account disablement) was staged, pending human deconfliction.

4. Containment

Containment was deliberately held in reserve rather than executed pre-emptively. Isolating a production SQL server and disabling the client's primary IT admin account carries real operational damage; with telemetry leaning benign and a fast deconfliction path available, verification-first was the proportionate call — with isolation ready to trigger immediately if contact failed or the story didn't corroborate.

The deconfliction itself was designed to be resistant to the alternative hypothesis:

  • Phone first, not email. If the competing explanation is a compromised admin account, the attacker may also control that account's mailbox. Voice contact with the known individual defeats that. The administrator confirmed verbally that he executed the command.
  • Written confirmation second, to create a documented evidence trail: he was troubleshooting a failing backup product and reset the server's shadow copies as part of remediation.
  • Story corroborated against telemetry. Backup troubleshooting on a SQL server is consistent with every observed artifact — interactive session, plain syntax, admin account, no precursor activity.

During the call, the administrator asked for endpoint protection to be paused for a few hours while he finished the work. I declined the pause and instead applied a time-boxed suppression scoped to the single detection rule on the single host. He got a quiet maintenance window; the server kept full EDR coverage for everything else. Pausing protection on a production database server — precisely the asset and moment an intruder would choose — was not an acceptable trade for alert convenience.

5. Remediation & Recovery

  • Alert closed as a benign true positive with the verification method fully documented (named individual, voice + written confirmation, timestamps).
  • Deconfliction outcome reported back to the managed SOC, closing the escalation loop and preventing duplicate escalations for the same maintenance activity.
  • Suppression removal scheduled for the end of the maintenance window — no permanent suppression of a T1490 rule was permitted on a production server.
  • Post-maintenance validation planned: confirm shadow copies are regenerating (vssadmin list shadows), which simultaneously verifies the client's restore points are healthy and the detection surface is fully re-armed, and confirm the underlying backup product issue is resolved.

6. Lessons Learned

What worked: Real-time rule detection put the alert in front of a human roughly two minutes after execution. Phone escalation from the SOC matched the urgency of the technique. Telemetry-first triage produced a calibrated hypothesis before any contact was made, and voice-first deconfliction closed the case with evidence that would survive scrutiny either way.

What didn't: There was no pre-agreed change-notification channel for the client's internal IT to flag planned maintenance involving security-sensitive operations — this entire escalation was avoidable with a one-line heads-up. The client's instinct to request a full protection pause also revealed a gap in shared understanding of what EDR suppression can do.

What changed as a result: Proposed a lightweight maintenance pre-notification practice for client IT admins performing operations that intersect known detection rules (VSS operations, backup catalog changes, boot configuration). Standardized the internal playbook response to "pause protection" requests: scoped, time-boxed rule suppression with a mandatory removal task — never agent pause.
